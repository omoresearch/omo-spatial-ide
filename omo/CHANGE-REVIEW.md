# Read-only project change review

## Milestone contract

Expose actual local Git changes next to conventional code access. The first-person terminal/browser screens remain physical world surfaces. Review is a normal readable code panel, not a replacement terminal. It lists changes and opens explicit read-only unified patches, plus the real file in Theia's existing editor when safe.

The physical Code screen is on the back-left wall. Click it within reach, or choose **Code** in the header. **Open project file** retains the existing README/file-picker editor route. **Back to world** restores walking at the same position and leaves the last read snapshot on that physical screen (first 22 lines, at most 100 characters per line; not an editable code buffer). Changing projects clears the preview. No Git contents are read before the user opens review, and patches are not prefetched from the file list.

- Fixed additive RPC contract: `extension/src/common/git-review-protocol.ts`.
- Parent owns frontend controller, panel, widget/DI wiring and actual-app acceptance.
- Backend builder owns ONLY `extension/src/node/git-review.ts` and `extension/test/git-review.test.cjs`. No changes to protocol, DI, dependencies, runtime or shared state.
- `GitReviewBackend` implements `GitReviewService` with `list(projectUri)` and `diff({projectUri,path})`. Export the class under that exact name.
- Operate inside an existing local `file:///` project directory; support a project nested inside a larger Git repository without exposing changes outside the project. Non-Git folders get a clear error, not fabricated empty status.
- Return at most 200 entries, with `truncated=true` if more exist. Preserve two-character Git status and literal relative paths, including spaces and non-ASCII. Parse NUL-delimited status. Disable rename detection in this increment so renames appear as add/delete, not guessed paths.
- Diff is working tree versus HEAD, covering staged and unstaged combined. Untracked files use real Git no-index diff versus empty input. Unborn repositories support new-file review without creating a commit. Missing files/deletions remain readable as real diffs where a HEAD exists.
- Bound Git commands to 10 seconds, 2 MiB captured output and a 256 KiB returned patch. Refuse oversized/binary/non-UTF-8 patches clearly; no silently truncated or invented hunks. Use execFile/spawn argument arrays, never a shell. Git no-index exit 1 is a normal difference result.
- Git reads must not stage, commit, checkout, reset, modify the index, fetch, invoke remote commands, external diff/textconv helpers, clean/process filters or fsmonitor hooks. Set `GIT_OPTIONAL_LOCKS=0`, `--no-pager`, literal pathspecs, `core.fsmonitor=false`, `--no-color`, `--no-ext-diff` and `--no-textconv` where relevant. Read configured filter names and override their clean/smudge/process programs and required flags for each command without rewriting Git configuration. Review compares raw saved content rather than running repository conversion programs.
- A diff request must select an exact path from a fresh scoped change list. Refuse absolute paths, traversal, malformed types, Git-internal paths and outside-project symlinks. Do not URI-decode or repair path tokens. Only return an editor URI for an existing regular file whose real path is within the selected project. Preserve filenames beginning with '-' as literal paths.
- Only read a patch on explicit selection. Status review carries no terminal output, clipboard data, browser page, prompt or agent command. No real agent/provider calls in tests.
- Tests use owned temporary Git repos under the configured scratch/evidence directory, never an existing developer repo. Prove tracked edits, index+working-tree combination, untracked files, deletion, unborn HEAD, nested project scoping, hostile filenames, rejected paths/symlinks, disabled external helpers and unchanged index/worktree/head after review.
- The real-browser review test starts its own loopback app on an OS-selected port, with an owned Theia profile/runtime directory/socket and a temporary parent Git repo containing a nested project. It creates the baseline before UI review, proves an edited parent file is not listed, and closes only its own process group/browser/socket before deleting its fixture. It never writes test content into the source repository's demo project.
- Snapshot staleness is explicit: refresh to see later saved edits. No Accept/Revert/Commit action is introduced.
