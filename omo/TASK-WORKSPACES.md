# Task workspaces

The local task workspace backend is connected to the room's **Task workspaces** view.

## Contract

The backend is registered on:

`/services/omo-task-workspaces`

The RPC target is a frozen, null-prototype facade exposing exactly `list`,
`create` and `getTaskWorkspace`. It does not expose the backend class or its
TypeScript-private manifest helpers.

The protocol exports `TaskWorkspaceService` and provides:

- `list(projectUri)`
- `create({ projectUri, name, confirmedCreate })`
- `getTaskWorkspace(worktreeUri)`

A returned task workspace contains its server-generated id, canonical source URI,
worktree URI, `omo/task/<id>` branch, captured base HEAD, display name, UTC
creation time, and `sourceHasChanges`.

`create` requires `confirmedCreate: true`. The name is display-only. It is 1 to
80 characters and cannot contain control characters.

The source URI must resolve to the existing top-level directory of a local Git
repository. A URI for a subdirectory is refused. The backend removes only Git's
final LF/CRLF record terminator from `rev-parse --show-toplevel`, so a valid
repository directory can end in spaces. The source can be dirty. The backend
captures HEAD and creates the worktree from that commit only. It does
not copy tracked edits, untracked files, or other dirty state. When the source
was dirty, `sourceHasChanges` is true. The create UI always warns that only the
captured commit is copied, and requires a name, an explicit checkbox and a separate
Create action. No worktree is created merely by entering or confirming the form.

## Persistence and safety

State is stored only below:

`RuntimeHost.locations.dataDir/task-workspaces/`

The manifest is bounded and written through a same-directory temporary file,
fsync, and rename. Worktrees are registered only after Git has created and
verified them. A malformed or oversized manifest, symlink, traversal path,
missing registered worktree, or unknown worktree directory causes a bounded
error. The backend never deletes an existing path or tries to repair partial
state.

Creates use both an in-process queue and an atomic state-directory lock. IDs,
branches, and worktree paths are generated by the backend. Git receives argv
arrays, not shell commands. The Git environment strips inherited Git scope and
config variables, disables global/system config, locks, terminal prompts and
pager use, sets `GIT_NO_LAZY_FETCH=1`, and uses no aliases. Hooks, fsmonitor,
automatic submodule recursion, clean/smudge/process filters, and required filter
flags are disabled for Git operations. Git commands have time and output limits.

A source or newly created worktree with `extensions.partialClone`, a configured
remote partial-clone filter, or a true remote promisor flag is refused before
HEAD/status or checkout work. The backend does not fetch, invoke a remote
helper, or log in. Partial-clone refusal is fail-closed even when the source
still has a locally readable HEAD.

Worktree creation uses `git worktree add --no-checkout`. After Git creates and
the backend verifies the owned directory, it reads effective filter keys again
from that new linked-worktree gitdir. This matters because a source-local
`includeIf.gitdir` rule can enable a filter only for the new worktree. The
initial `checkout <captured-head> -- .` runs only in that owned directory with
hooks and all discovered filter commands disabled. This populates the new worktree
without detaching its HEAD from the generated task branch and uses no force flag.
The source checkout and source index are not reset or written.

This backend has no APIs for delete, apply, start, merge, reset, force, stage,
commit, remove, provider access, network access, or automatic runtime/agent/
browser starts.

`getTaskWorkspace(worktreeUri)` is read-only continuation authority. It accepts
only an existing canonical `file://` directory, requires that the argument is
exactly the canonical URI, validates the manifest and every registered
worktree, and returns a copied manifest record only when that exact URI is
registered. Unknown or symlink/non-canonical paths are refused or return
`undefined`; the method never searches arbitrary paths or starts, promotes or
deletes a worktree.

## Source test evidence

The source test is:

`extension/test/task-workspaces.test.cjs`

It uses real temporary Git repositories and an in-test TypeScript transpile
loader. It does not emit files. The test covers:

- explicit confirmation and safe names;
- dirty-source warning, exact HEAD capture, and no dirty/untracked copying;
- unchanged source HEAD, index, and files;
- independent worktree edits;
- stable list after service recreation and exact-project filtering;
- parent-repository fallback refusal;
- malformed and oversized manifests;
- symlinked state, traversal records, unknown directories, and missing state;
- concurrent unique creates;
- repository roots ending in a space without changing the canonical path;
- real hook and filter helper sentinels, including a filter enabled only by a
  new-worktree `includeIf.gitdir` rule;
- configured promisor/partial-clone refusal without a remote helper.

The sentinel tests are live child-only reproducers. An intentionally unsafe
checkout runs the helper and fails. The production path then uses `--no-checkout`,
rediscovers the new-worktree filter keys, and checks out successfully with an
empty sentinel. The partial-clone fixture sets `remote.origin.promisor=true`,
`remote.origin.partialclonefilter=blob:none`, and `extensions.partialClone`.
The backend refuses before any fetch-capable operation; the remote-helper
sentinel remains absent.

Commands run in this worktree:

- Red: after adding the trailing-space and partial-clone assertions,
  `node --test extension/test/task-workspaces.test.cjs` returned 8 passing and
  3 failing. The real backend failures were the trimmed trailing-space root
  and missing partial-clone refusal. The conditional-filter fixture also first
  exposed an invalid test-config assertion, which was corrected before green.
- Green: `node --test extension/test/task-workspaces.test.cjs` returned 11
  passing, 0 failing, 0 skipped.

No fetch, remote helper, login, build, install, browser, service, provider, agent,
implementation-worktree commit, or push was run.

## Frontend and actual-page checks

The frontend proxy, explicit creation form and registered-worktree list are wired
into the room header. **Open task project** is a separate explicit folder-open
action. It never starts an agent or applies code back to the source. The worktree
gets its own project URI and room/runtime bindings.

The controller rejects stale list/create receipts, duplicate submits, foreign or
malformed records and stale open targets. A host-side service facade checks the
current project and open panel both before and after each request, including the
gap before React effects observe a project change. Folder opening checks the
captured source URI against the host's current project again. Leaving during an
already submitted creation does not claim to cancel or roll back the backend;
return to the original source and refresh to find a completed worktree.

`task-workspaces-real-app.cjs` owns a real Git source, app, browser and tmux socket.
It tests explicit confirmation, persisted refresh, named-branch checkout, clean
commit-only copying from a dirty source, unchanged source HEAD/index/files,
explicit folder opening and an independent edit through the physical terminal.
All agent executables are pinned to no-network fixtures; this test starts none.

If creation fails after Git has created a worktree, the backend leaves that owned
state intact and fails closed on an unregistered path. There is no delete/recovery
API. Inspect the task-workspace manifest and Git worktree metadata before a scoped
manual recovery; do not delete the whole runtime data directory.

Limits: the UI expects the canonical local Git root URI. Partial clones are
refused. This trusted-local alpha does not provide authenticated multiplayer,
automatic code promotion, isolated OS permissions or a filesystem sandbox for
agents. A worktree separates edits; an agent still has its normal CLI permissions.
